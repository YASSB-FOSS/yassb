The mental model

Content, markup and logic. Each in its place.

Store content in JSON or Markdown, compose pages in HTML, and use TypeScript functions to turn data into markup. HTML comment directives connect the pieces, making it clear where content comes from and how each page is built.

1Data

Content in JSON or Markdown.

Content lives in JSON or Markdown files, apart from markup and code. Update the data file, and rebuild every page that uses it.

Datasrc/app/data-sources/talks.json

[
  { "title": "Static sites in 2026", "date": "2026-03-12", "place": "Milan" },
  { "title": "Agents and the web", "date": "2026-05-02", "place": "Online" },
  { "title": "Shipping with YASSB", "date": "2026-09-18", "place": "Turin" }
]

2UI

HTML pages with reusable components.

Pages are plain HTML. Write a block once as a component and reuse it anywhere. A directive marks where data goes: it names the data file and the renderer that turns it into HTML.

UIsrc/app/pages/index.html

<main>
  <!-- component="site/header.html" -->
  <h1 data-t="HOME.TITLE">Talks</h1>
  <ul class="talks">
    <!-- create-from-data-source="talks.json" renderer="talkList" options="{"limit":3}" -->
  </ul>
</main>

3Logic

Render data with TypeScript at build time.

A renderer is a typed function: it gets the data and options from the directive and returns HTML, with any loop or condition you need. Custom directives are TypeScript too. All of it runs at build time: visitors get static HTML.

Logicbuilder/renderers.ts

import { RendererProps } from 'yassb-web';

type Talk = { title: string; date: string; place: string };

export function talkList({ source, options }:
  RendererProps<Talk[], { limit?: number }>) {
  return source
    .slice(0, options?.limit)
    .map(t => t.place === 'Online'
      ? `<li>${t.title} · <a href="/live">watch live</a></li>`
      : `<li>${t.title} · ${t.place}</li>`)
    .join('');
}
